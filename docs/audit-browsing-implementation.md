# Tenant and platform audit browsing

Tenant audit requires current tenant administration access. The separate platform trail requires current global-super-admin access; its optional tenant filter selects recorded target-tenant references, without mixing tenant-scoped audit rows into that trail. Each page reads PostgreSQL, reauthorizes, and reapplies the 365-day boundary, active dependency holds, and permanent expiry fences. Audit content is never changed by browsing.

Both endpoints accept `period=recent` (the default last 30 days) or `period=retained` (all still-readable retained and protected records). `from_at` is inclusive and overrides the default lower bound; `to_at` is exclusive. Times require an explicit ISO 8601 timezone and are normalized to UTC. Exact filters are `action`, `actor_id` (UUID or `system`), `affected_principal_id`, and `resource_id`. Platform audit also accepts `tenant_id`. Default/max page sizes remain 50/200.

Filters follow the current writers' actual evidence shapes. Affected principals match a direct `principal_id`, `changes[].principal_id`, or `initial_grants[].principal_id`; the full prior grant roster does not imply that all its principals changed. Resources match the scope tenant, recorded `target_tenant_id`, or recorded source-repair `head_id`. Platform tenant filtering currently matches `target_tenant_id`. New audit producers must explicitly extend these mappings when introducing a different affected-reference shape. Browsing does not manufacture missing event coverage or verification fields.

Opaque 15-minute cursors bind scope, actor/session, normalized filters, deterministic newest-recording-time/event-ID ordering and deployment epoch. They retain the first page's recording upper watermark and effective lower bound. New records do not reshuffle later pages; released holds or lost access can remove previously eligible records. Minimal recorded source-item references include an availability check without loading or reconstructing source content.

The dedicated audit browser is connected to tenant Access audit and Platform administration. It shows browser-local times and the timezone, with the stored UTC instant in details. Historical actor labels and before/after/verification evidence are escaped plain text. Protected records and unavailable recorded source references are labeled. Filters and pagination are read-only; there is no audit editor or export workflow.

Local verification: four PostgreSQL integration cases execute through the restricted `keep_api` role and cover time/retention/holds/fences, exact evidence filters, captured labels, fixed cursors, current privilege loss and platform-scope separation. The existing dependency-protected expiry regression explicitly requests the retained period and passes. Mocked browser tests separately cover applied filter/cursor binding, platform tenant selection, plain-text details and clearing protected results after permission loss. Company-service qualification and production-volume query budgets remain external delivery checks.
